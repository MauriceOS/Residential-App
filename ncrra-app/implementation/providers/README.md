# Provider adapter activation boundary

The adapter port is now compiled and containerised, and its `/healthz` endpoint confirms that the process is available. Its `/readyz` endpoint deliberately returns **503** while `NCRRA_PROVIDER_INTEGRATION_ENABLED=false`; this is the required default. When that flag is enabled, readiness still remains **503** unless an approved, unexpired agreement ledger record covers an allowed provider action. The registry defines KPLC as managed operations and SGR/Jambojet as official handoffs, not undocumented API connections.

The `agreement-record` command records opaque agreement and approval references, the authorised approver, expiry and permitted actions into a restricted ledger. It does not sign legal documents or store credentials. To propose a real activation, a deployment pull request must provide a provider-specific agreement and approval reference, vault credential reference in the reviewed registry, the provider’s documented integration specification and security approval, and an approved `NCRRA_PROVIDER_INTEGRATION_ENABLED=true` change in a protected production environment. The mobile client and API service must not contain those credentials.
